# Config（/config 設定）

> 出典: [Claude Code 公式ドキュメント（設定）](https://code.claude.com/docs/en/settings)

意識して運用しているのは以下の2つ。

---

## 1. Switch models when a message is flagged → `true`（デフォルト維持・理解した上で運用）

### 何を
Claude Code既製の設定（設定キー: `switchModelsOnFlag`、デフォルト: `true`、v2.1.170以降）。

**Claude Fable 5の安全分類器がリクエストをフラグした時、自動でOpus系モデルに切り替えて再実行するかどうか**を制御する。

### 背景：なぜこの設定が存在するか
Fable 5には特定領域の安全分類器が内蔵されており、以下のドメインでフラグが立つ：

1. **攻撃的サイバーセキュリティ技術**（エクスプロイト・マルウェア・攻撃ツール構築など）
2. **生物学・生命科学のデュアルユース領域**（ウイルス学・毒性学・創薬・分子設計など）
3. **モデルの思考プロセスの抽出要求**（Fable 5への蒸留攻撃）
4. フロンティアLLM開発タスクの一部（分散トレーニング基盤・MLアクセラレータ設計など）

フラグが立つと、FableではなくOpusにフォールバックして同じリクエストを再実行する仕組み。切り替え発生時は通知が出て、回答にモデル名がラベル付けされる。**切り替え後はモデルピッカーがOpusに固定されたまま**会話の残りに適用される点に注意。

参考:
- [Why Claude switched models in your conversation with Fable 5（公式サポート記事）](https://support.claude.com/en/articles/15363606-why-claude-switched-models-in-your-conversation-with-fable-5)
- [oikon48氏のポスト](https://x.com/oikon48/status/2064937790010503347)
- [Qiita解説記事](https://qiita.com/yurukusa/items/74d60654678f8915f50d)

### どの作業のために
私は **`true`（デフォルト）のまま**運用している。フラグ時に自動でOpusへフォールバックして作業が止まらないことを優先する判断。逆に「勝手にモデルが変わるのが嫌で、切り替えの主導権を持ちたい」なら `false` にすると、フラグ時に会話が一時停止して「プロンプト編集して再試行」か「手動切り替え」かを選べる。

**この設定は「どちらにするか」より「存在と挙動を知っていること」が重要**。切り替え後はモデルピッカーがOpusに固定されたままになるので、気づかずOpusで作業し続ける事故はtrue運用の注意点。

### 入れる前と後（③）
- **知る前**: フラグ発生時に「なぜ急にOpusになった？」と混乱する。回答の質の変化の原因が分からない
- **知った後**: フォールバック発生を通知とモデルラベルで即認識し、必要ならFableに戻す判断ができる

## 2. Dynamic workflow size → `unrestricted`

### 何を
Claude Code既製の設定（設定キー: `workflowSizeGuideline`、v2.1.202以降）。

Claude Codeが動的に組み立てる**ワークフロー（マルチエージェント・オーケストレーション）のエージェント数ガイドライン**を指定する。強制上限ではなく「アドバイス」としてモデルに渡される。

### 取りうる値

| 値 | 目安 |
|---|---|
| `unrestricted` | ガイドラインなし。タスクに応じてClaudeが自由に規模を決める |
| `small` | 5エージェント未満 |
| `medium`（現デフォルト、v2.1.219以降） | 15エージェント未満 |
| `large` | 50エージェント未満 |

補足: ワークフローが25エージェント超 or トークン見積もり150万超で「Large workflow」警告が出る（実行は止まらない）。

### どの作業のために
`/deep-research` や `/ultrareview` のような大規模ファンアウト系タスクで、**エージェント数の制約なしに徹底的に調査・検証させる**ため。網羅性重視の調査・レビューではエージェント数を絞ると取りこぼしが出る。

### 入れる前と後（③・実体験）
- **前（medium）**: ワークフローが15エージェント未満に自主規制され、大規模調査で網羅性が落ちることがある
- **後（unrestricted）**: タスクの要求どおりの規模でファンアウト。**実例: この共有会資料の作成では、deep-research 6体並列＋裏取りresearch 6本＝計12サブエージェント（全Sonnet 5）が1セッションで走り、環境変数からCursorプラグインまでの全項目調査と6件の食い違い検証を数時間で完了した**。トークンコストは増えるが調査・レビューの質を優先できる
