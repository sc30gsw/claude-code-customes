# OKR Skill

## 概要

チーム目標と役割に基づいて四半期OKRを作成する高度なインタラクティブスキル。3つのObjectiveと各3つのKey Result（合計9つ）を生成し、70%/100%の達成基準を含めます。

## アクティベーショントリガー

- 四半期OKRを作成する時
- チーム目標から個人目標を設定する時
- OKRの改善・洗練が必要な時

## 使用方法

```bash
/okr --role <role> "<team-goals>" [options]
```

## 必須引数

| 引数 | 説明 |
|------|------|
| `--role <role>` | 役割（engineer, pm, designer, qa, data-analyst など） |
| `<team-goals>` | チームレベルの目標（自然言語テキスト） |

## オプション

### ファイル入力オプション
| オプション | 説明 |
|-----------|------|
| `--sample <path>` | 参照OKRサンプルファイル |
| `--team-okr <path>` | チームOKRファイルを参照 |
| `--previous <path>` | 前四半期OKRを参照 |

### 出力オプション
| オプション | 説明 |
|-----------|------|
| `--output <path>` | 出力ファイルパス |
| `--format <type>` | 出力形式: markdown/json/yaml |

### インタラクティブ機能
| オプション | 説明 |
|-----------|------|
| `--interactive` | インタラクティブOKR作成モード |
| `--refine` | 曖昧な目標を質問を通じて洗練 |

## 使用例

```bash
# 基本的な使用法
/okr --role engineer "20% revenue increase, NPS +10, 2 new product launches"

# サンプル参照付き
/okr --role engineer "売上20%増加" --sample ./okrs/samples/engineer.md

# インタラクティブモードと永続化
/okr --role engineer --interactive --persist
```

## 出力形式

### Objectives（合計3つ）
- 定性的かつインスピレーションを与える
- チーム目標との明確な整合性
- 達成可能でありながら挑戦的

### Key Results（各Objectiveに3つ、合計9つ）
各KRには以下を含む：
- **70%目標**: 標準目標（努力で達成可能）
- **100%目標**: ストレッチ目標（全てがうまくいった時に達成可能）

## 役割別の考慮事項

### Engineer
- 技術的な成果物、コード品質、パフォーマンス
- 開発効率、技術的負債の削減
- 学習とスキル開発

### PM（プロダクトマネージャー）
- プロダクト指標（DAU、リテンション）
- 機能リリース、ユーザーフィードバック
- ステークホルダー調整

### Designer
- UX/UI改善指標
- デザインシステム、ユーザビリティテスト
- ブランド一貫性

### QA
- 品質指標、テスト自動化
- リリース品質ゲート
- 品質プロセス改善

## 出力例

```markdown
# Q1 2024 OKR: エンジニア

## Objective 1: プロダクトの信頼性を向上させる

### Key Results
| KR | 70%目標 | 100%目標 |
|----|---------|----------|
| 1.1 | APIレスポンスタイム200ms以下 | 150ms以下 |
| 1.2 | エラー率0.5%以下 | 0.1%以下 |
| 1.3 | テストカバレッジ80% | 90% |

## Objective 2: 開発効率を最大化する
...

## Objective 3: 技術的負債を解消する
...
```

## ベストプラクティス

1. **SMARTなKR** - 具体的で測定可能なKey Resultを設定
2. **アウトカム重視** - アウトプットではなくアウトカムを測定
3. **挑戦的だが現実的** - 70%達成が努力で可能なレベル
4. **チーム整合性** - チームOKRとの明確な関連性
5. **定期レビュー** - 四半期中の進捗確認を計画
