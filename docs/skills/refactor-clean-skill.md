# Refactor Clean Skill

## 概要

テスト検証とロールバック機能を備えた、安全なデッドコードの特定と削除を行うスキル。コードベースの健全性を維持しながらクリーンアップを実施します。

## アクティベーショントリガー

- コードのクリーンアップが必要な時
- 使用されていないコードを特定したい時
- 依存関係の整理が必要な時
- リファクタリング前の準備時

## コア原則

### 1. 安全性優先
テストなしでコードを削除しない

### 2. 段階的削除
一度に多くのコードを削除しない

### 3. 検証必須
削除後は必ずテストを実行

## ワークフロー

### Step 1: デッドコード分析ツールの実行
```bash
# 未使用のexportとファイルを検索
npx knip

# 未使用の依存関係を検索
npx depcheck

# 未使用のTypeScriptエクスポートを検索
npx ts-prune
```

### Step 2: レポート生成
`.reports/dead-code-analysis.md`に包括的なレポートを生成

### Step 3: 重要度による分類

| 重要度 | 対象 | 説明 |
|--------|------|------|
| SAFE | テストファイル、未使用ユーティリティ | 安全に削除可能 |
| CAUTION | APIルート、コンポーネント | 確認が必要 |
| DANGER | 設定ファイル、メインエントリポイント | 削除は慎重に |

### Step 4: 安全な削除のみ提案
SAFE分類のアイテムのみを削除候補として提案

### Step 5: 削除前の検証
1. 完全なテストスイートを実行
2. テストがパスすることを確認
3. 変更を適用
4. テストを再実行
5. テストが失敗した場合はロールバック

### Step 6: サマリー表示
```markdown
## クリーンアップサマリー

### 削除済み
- src/utils/deprecated.ts (未使用)
- src/components/OldButton.tsx (未使用)

### 削除対象外
- src/api/routes.ts (CAUTION: API)

### 削減効果
- ファイル数: -2
- コード行数: -150
```

## ツール詳細

### knip
- 未使用のexport、ファイル、依存関係を検出
- プロジェクト全体のデッドコード分析

### depcheck
- package.jsonの未使用依存関係を検出
- devDependenciesも含めて分析

### ts-prune
- TypeScriptの未使用エクスポートを検出
- モジュール境界での不要コードを特定

## ベストプラクティス

1. **テストファースト** - 削除前にテストを実行
2. **小さく始める** - 確実に安全なものから削除
3. **git履歴確認** - 最近変更されたコードは慎重に
4. **ドキュメント確認** - 外部で参照されていないか確認
5. **段階的実行** - 一度に多くを削除しない

## 成功指標

- デッドコードが正常に特定される
- 削除後もテストがパス
- ビルドが成功
- 本番環境で問題が発生しない
