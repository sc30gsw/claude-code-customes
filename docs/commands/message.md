# コミュニケーションテキスト生成コマンド

チャット、メール、チケット、レポートなど、様々な業務シーンに適したコミュニケーションテキストを生成するコマンドです。

## `/message` - コミュニケーションテキスト生成コマンド

### 概要
業務における様々なコミュニケーションシーンに対応したテキストを生成します。チャットメッセージ、ビジネスメール、イシューチケット、進捗レポート、お知らせ、タスクアウトラインなど、用途に応じた適切なフォーマットと文体で出力します。

### 基本構文
```bash
/message <input> [options]
```

### 引数
- `input`: メッセージに変換するコンテンツ（必須）
  - 入力形式: 引用符で囲んだテキスト、ファイルパス、またはトピックの説明

### オプション

| オプション | 短縮形 | 説明 | デフォルト |
|-----------|--------|------|-----------|
| `--format` | `-f` | 出力形式 | `chat` |
| `--lang` | `-l` | 出力言語（ja/en） | `ja` |
| `--length` | | メッセージの長さ（short/medium/long） | `medium` |
| `--context` | `-c` | 追加コンテキスト | なし |
| `--output` | `-o` | 出力ファイルパス（省略時はコンソール表示） | なし |
| `--to` | `-t` | 宛先タイプ（team/manager/client/external） | `team` |
| `--urgent` | `-u` | 緊急フラグ | false |
| `--priority` | `-p` | 優先度（high/medium/low） | `medium` |

### 出力形式一覧

| 形式 | トーン | 最適な用途 |
|------|--------|-----------|
| `chat` | カジュアル | Slack、Teams、Discordメッセージ |
| `email` | フォーマル | ビジネスメール、正式なコミュニケーション |
| `ticket` | テクニカル | Jira、GitHub Issues、バグレポート |
| `report` | 構造的 | 進捗レポート、週次・月次サマリー |
| `announcement` | 情報伝達 | 社内通知、チームアナウンス |
| `outline` | アクション指向 | タスクチェックリスト、作業手順書 |

### 宛先別トーン調整（`--to`）

| 宛先 | トーン | 特徴 |
|------|--------|------|
| `team` | カジュアル | 親しみやすい、簡潔、カジュアル |
| `manager` | 丁寧 | 敬意を込めた、構造的、プロフェッショナル |
| `client` | フォーマル | 非常に丁寧、詳細、プロフェッショナル |
| `external` | ビジネス | 初回連絡向け、礼儀正しい |

### 緊急度オプション

**`--urgent`フラグ:**
- 日本語: `【緊急】`または`【至急】`プレフィックスを追加
- 英語: `[URGENT]`プレフィックスを追加

**`--priority`レベル:**
- `high`: 重要性を強調、迅速な対応を要請
- `medium`: 標準的なトーン（デフォルト）
- `low`: 柔軟性を示す、「お時間のある時に」

### 使用例

#### チャットメッセージ
```bash
/message "明日お休みいただきます" --format chat
```

#### マネージャーへのメール
```bash
/message "週次進捗報告" --format email --to manager
```

#### 緊急のお知らせ
```bash
/message "今夜サーバーメンテナンスを実施します" --format announcement --urgent
```

#### 進捗レポート（ファイル入力）
```bash
/message ./notes.md --format report --lang ja
```

#### タスクアウトライン
```bash
/message "ユーザー認証機能の実装" --format outline --context "OAuth2サポートを追加"
```

#### クライアント向け高優先度メール
```bash
/message "プロジェクト状況報告" --format email --to client --priority high
```

#### Jiraチケット
```bash
/message "ログインバグ修正" --format ticket --context "パスワードリセット後にログインできない"
```

### 処理ワークフロー

#### Step 1: 入力の解析
1. 入力がファイルパス（`.md`、`.txt`等）の場合、`Read`ツールでコンテンツを取得
2. 入力が引用符で囲まれたテキストの場合、直接使用
3. `--context`があれば補足情報として適用

#### Step 2: 緊急プレフィックスの適用
`--urgent`が設定されている場合、適切なプレフィックスを追加：
- 日本語: `【緊急】`または`【至急】`
- 英語: `[URGENT]`

`--priority high`の場合、本文で緊急性を強調。

#### Step 3: 宛先に基づくトーン決定
`--to`に基づいて言葉遣いのフォーマル度を調整：
- **team**: カジュアル、フレンドリー（例: 「お疲れ様！」）
- **manager**: 丁寧、敬意を込めた（例: 「お疲れ様です」）
- **client**: フォーマル、プロフェッショナル（例: 「いつもお世話になっております」）
- **external**: ビジネスフォーマル（例: 「初めてご連絡いたします」）

#### Step 4: 形式に基づく生成

各形式の詳細なテンプレートと構造については、以下のセクションを参照してください。

#### Step 5: 長さの調整
`--length`に基づいて調整：
- **short**: 2-3文、要点のみ
- **medium**: 標準的なフォーマットで適度な詳細
- **long**: 完全なコンテキストを含む包括的な内容

#### Step 6: 出力の生成
1. フォーマットされたメッセージを生成
2. `--output`が指定されている場合、`Write`ツールでファイルに書き込み
3. それ以外はレスポンスに直接表示

### 形式別テンプレート

#### Chat形式
**トーンガイドライン:**
- カジュアル、フレンドリーな言葉遣い
- リストには箇条書きを使用
- 絵文字の使用OK
- 簡潔に

**構造:**
```
[挨拶 - 任意]

**[トピック/タイトル]**

- ポイント1
- ポイント2
- ポイント3

[締めの言葉 - 任意]
```

#### Email形式（日本語）
**トーンガイドライン:**
- プロフェッショナル、丁寧な言葉遣い
- 正式な挨拶と締めの言葉
- 構造化された段落
- 明確な件名

**構造:**
```
件名: [件名]

[宛名] 様

お疲れ様です。

[導入 - メールの目的]

【[セクションヘッダー]】
・[ポイント1]
・[ポイント2]

[締めの文]

よろしくお願いいたします。
```

#### Email形式（英語）
**構造:**
```
Subject: [Subject Line]

Dear [Recipient],

[Opening paragraph - purpose]

[Body - key points]

[Closing paragraph - next steps/call to action]

Best regards,
[Your name]
```

#### Ticket形式
**トーンガイドライン:**
- テクニカル、正確な言葉遣い
- 構造化されたセクション
- 明確な受け入れ条件
- Markdownフォーマット

**構造:**
```markdown
## Summary
[簡潔な一行説明]

## Background
[コンテキストとなぜこれが必要か]

## Requirements
- [要件1]
- [要件2]

## Acceptance Criteria
- [ ] [基準1]
- [ ] [基準2]

## Additional Notes
[オプション: 技術的詳細、リンク、参考資料]
```

#### Report形式（日本語）
**トーンガイドライン:**
- 明確、構造化されたプレゼンテーション
- 可能な限りデータ駆動
- アクション指向の結論

**構造:**
```markdown
# [レポートタイトル]

**期間**: [対象期間]
**報告者**: [名前]
**報告日**: [日付]

## サマリー
[1-2文で要約]

## 実績
- [完了したこと1]
- [完了したこと2]

## 進行中
- [進行中のタスク1]
- [進行中のタスク2]

## 課題・懸念事項
- [課題があれば記載]

## 次のアクション
- [次にやること]
```

#### Announcement形式（日本語）
**トーンガイドライン:**
- 明確、情報伝達的
- スキャンしやすい
- 必要な詳細をすべて含む

**構造:**
```
【お知らせ】[タイトル]

[本文 - 何についてのお知らせか]

■ 詳細
・[ポイント1]
・[ポイント2]

■ 対象者
[誰に関係するか]

■ 期日・日程
[いつまでに何をするか]

ご不明点があれば、[連絡先]までお問い合わせください。
```

#### Outline形式（日本語）
**トーンガイドライン:**
- アクション指向
- 明確なステップバイステップ構造
- 追跡用チェックボックス

**構造:**
```markdown
# [タスク名] - 作業アウトライン

## 目的
[このタスクで達成すること]

## 前提条件
- [ ] [必要な準備1]
- [ ] [必要な準備2]

## 作業手順

### Step 1: [ステップ名]
- [ ] [具体的なアクション]
- [ ] [具体的なアクション]

### Step 2: [ステップ名]
- [ ] [具体的なアクション]
- [ ] [具体的なアクション]

### Step 3: [ステップ名]
- [ ] [具体的なアクション]

## 完了条件
- [ ] [何をもって完了とするか]

## 参考リンク
- [関連ドキュメント]
```

### 活用シーン
- **日常コミュニケーション**: チームへの連絡、休暇申請、進捗共有
- **ビジネスメール**: 上司への報告、クライアントへの連絡、外部への初回コンタクト
- **プロジェクト管理**: Jira/GitHubチケット作成、バグレポート
- **定期報告**: 週次・月次レポート、プロジェクト進捗報告
- **社内通知**: メンテナンス告知、ポリシー変更、イベント案内
- **作業計画**: タスク分解、手順書作成、チェックリスト生成

### Tips
- チャットでは絵文字がトーンを伝えるのに効果的
- メールでは常に明確な件名を含める
- チケットでは受け入れ条件を具体的に
- レポートでは可能な限り測定可能な成果を含める
- お知らせでは重要な日付/期限を強調
- アウトラインでは小さなアクション可能なステップに分解
- ファイル入力から変換する場合、すべてをコピーするのではなく要点を要約
- 外部ステークホルダーには`--to client`を使用して最大限のプロフェッショナリズムを確保

### 使用ツール
- `Read` - 入力ファイルの読み取り
- `Write` - 出力ファイルへの書き込み
- `Glob` - ファイル検索
- `Grep` - コンテンツ検索
- `TodoWrite` - 処理進捗管理
