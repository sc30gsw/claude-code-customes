# /update-codemaps - コードマップ更新コマンド

---
description: コードベース構造を分析し、アーキテクチャドキュメントを更新
---

## 概要

`/update-codemaps` コマンドは **doc-updater** エージェントを呼び出し、コードベースの構造を分析してアーキテクチャドキュメントを更新します。

## 機能

1. すべてのソースファイルをスキャンしてインポート、エクスポート、依存関係を分析
2. トークン効率の良いコードマップを生成
3. 前バージョンとの差分を計算
4. 30%以上の変更がある場合はユーザー承認を要求
5. 各コードマップに鮮度タイムスタンプを追加
6. レポートを保存

## 生成されるコードマップ

```
codemaps/
├── architecture.md  # 全体アーキテクチャ
├── backend.md       # バックエンド構造
├── frontend.md      # フロントエンド構造
└── data.md          # データモデルとスキーマ
```

## コードマップフォーマット

```markdown
# [エリア] コードマップ

**最終更新:** YYYY-MM-DD
**エントリポイント:** 主要ファイルのリスト

## アーキテクチャ

[コンポーネント関係のASCII図]

## 主要モジュール

| モジュール | 目的 | エクスポート | 依存関係 |
|----------|------|------------|---------|
| auth.ts | 認証処理 | login, logout | supabase |
| api.ts | APIクライアント | fetch, post | axios |

## データフロー

[このエリアのデータフローの説明]

## 外部依存関係

- パッケージ名 - 目的、バージョン
- ...

## 関連エリア

このエリアと相互作用する他のコードマップへのリンク
```

## 動作フロー

### 1. リポジトリ構造分析

```
a) すべてのワークスペース/パッケージを特定
b) ディレクトリ構造をマッピング
c) エントリポイントを見つける（apps/*, packages/*, services/*）
d) フレームワークパターンを検出（Next.js、Node.js等）
```

### 2. モジュール分析

```
各モジュールに対して：
- エクスポートの抽出（公開API）
- インポートのマッピング（依存関係）
- ルートの特定（APIルート、ページ）
- データベースモデルの発見（Supabase、Prisma）
- キュー/ワーカーモジュールの特定
```

### 3. コードマップ生成

構造化されたマークダウンファイルを生成

### 4. 差分計算と承認

```
変更が30%以上の場合:
- 差分を表示
- ユーザー承認を要求
- 承認後に更新
```

## ベストプラクティス

1. **単一の信頼源** - 手動で書かず、コードから生成
2. **更新タイムスタンプ** - 常に最終更新日を含める
3. **トークン効率** - 各コードマップを500行以下に保つ
4. **明確な構造** - 一貫したマークダウンフォーマットを使用
5. **リンク付き** - 関連ドキュメントを相互参照

## 使用タイミング

以下の場面で使用:
- 新しい主要機能追加後
- アーキテクチャ大幅変更後
- 定期的なドキュメント更新（週次推奨）
- 新メンバーのオンボーディング準備

## 他のコマンドとの連携

- `/update-docs` でドキュメント全体を更新
- `/plan` でアーキテクチャ変更を計画

## 関連エージェント

このコマンドは以下のエージェントを呼び出します:
`~/.claude/agents/doc-updater.md`
