# Kiro Spec Tasks Command

## 概要

仕様に対する実装タスクを生成するコマンド。設計ドキュメントに基づいて、段階的な実装計画を作成します。

## 基本情報

| 項目 | 値 |
|------|-----|
| コマンド | `/kiro:spec-tasks` |
| 引数 | `<feature-name> [-y]` |
| 用途 | 実装タスクの生成 |
| 許可ツール | Read, Write, Edit, MultiEdit, Glob, Grep |

## 前提条件

- 要件と設計が承認されていること
- `-y`フラグで自動承認可能

## タスク番号付けルール

```markdown
- [ ] 1. メジャータスク説明
- [ ] 1.1 サブタスク説明
  - 詳細項目 1
  - 詳細項目 2
  - _Requirements: X.X, Y.Y_

- [ ] 1.2 サブタスク説明
  - 詳細項目...
  - _Requirements: X.X_

- [ ] 2. 次のメジャータスク（1ではなく2!）
```

**重要**:
- メジャータスクは連番（1, 2, 3...）
- サブタスクはメジャー番号.連番（1.1, 1.2, 2.1...）
- 最大2レベルの階層（1.1.1は不可）

## タスク生成ルール

1. **自然言語での記述** - 実装の詳細ではなく達成する機能
2. **タスクの統合と進行** - 前のタスクの出力に基づく
3. **柔軟なサイズ** - 1-3時間のサブタスク
4. **要件マッピング** - `_Requirements: X.X_`形式
5. **コードのみ** - デプロイ/ドキュメントは除外

## 使用例

```bash
# タスクを生成
/kiro:spec-tasks user-authentication

# 要件と設計を自動承認してタスクを生成
/kiro:spec-tasks user-authentication -y
```

## タスク例

```markdown
# Implementation Plan

- [ ] 1. プロジェクト基盤とインフラの設定
  - 必要な技術スタックでプロジェクトを初期化
  - サーバーインフラとリクエスト処理を設定
  - データストレージとキャッシュレイヤーを確立
  - _Requirements: すべての要件に基盤設定が必要_

- [ ] 2. 認証・ユーザー管理システムの構築
- [ ] 2.1 コア認証機能の実装
  - バリデーションルール付きユーザーデータストレージを設定
  - 安全な認証メカニズムを実装
  - ユーザー登録機能を構築
  - _Requirements: 7.1, 7.2_
```

## 次のフェーズ

タスク生成後：
- `/kiro:spec-impl <feature-name>` - すべての保留タスクを実行
- `/kiro:spec-impl <feature-name> 1.1` - 特定タスクを実行
- `/kiro:spec-impl <feature-name> 1,2,3` - 複数タスクを実行
