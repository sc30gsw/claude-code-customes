# Kiro Validate Design Command

## 概要

インタラクティブな技術設計品質レビューと検証を行うコマンド。設計の品質を評価し、GO/NO-GOの判定を提供します。

## 基本情報

| 項目 | 値 |
|------|-----|
| コマンド | `/kiro:validate-design` |
| 引数 | `<feature-name>` |
| 用途 | 設計ドキュメントの品質レビュー |
| 許可ツール | Bash, Glob, Grep, Read, Task, WebFetch, WebSearch |

## 前提条件

- 設計ドキュメントが存在: `.kiro/specs/<feature>/design.md`
- 存在しない場合: `/kiro:spec-design <feature>`を先に実行

## レビュー方法論

- **フォーカス**: 重大な問題のみ - 最大3つの重要な懸念事項
- **形式**: 即座のフィードバックと改善提案を伴うインタラクティブな対話
- **結果**: 明確な根拠を伴うGO/NO-GO判定

## コアレビュー基準

### 1. 既存アーキテクチャとの整合性（Critical）
- 既存システム境界とレイヤーとの統合
- 確立されたアーキテクチャパターンとの一貫性
- 適切な依存関係の方向と結合管理
- 現在のモジュール構成と責任との整合

### 2. 設計の一貫性と標準
- プロジェクトの命名規則とコード標準への準拠
- 一貫したエラーハンドリングとロギング戦略
- 設定と依存関係管理への統一的アプローチ
- 確立されたデータモデリングパターンとの整合

### 3. 拡張性と保守性
- 将来の要件変更に対する設計の柔軟性
- 関心の分離と単一責任原則
- テスト可能性とデバッグの考慮
- ドキュメントとコードの明確さ要件

### 4. 型安全性とインターフェース設計
- 適切な型定義とインターフェース契約
- `any`型と安全でないパターンの回避
- 明確なAPI境界とデータ構造定義
- 入力検証とエラー条件のカバレッジ

## 出力形式

### Critical Issues（最大3つ）
```
🔴 **Critical Issue [1-3]**: [簡潔なタイトル]
**Concern**: [具体的な問題の説明]
**Impact**: [プロジェクトへの影響]
**Suggestion**: [具体的な改善提案]
```

### Design Strengths
設計の1-2の強い点を認識。

### Final Assessment
- **Decision**: GO / NO-GO
- **Rationale**: 判定の明確な理由
- **Next Steps**: 次に行うべきこと

## GO/NO-GO基準

### GO基準
- 重大なアーキテクチャの不整合なし
- 要件が適切に対処されている
- 実装パスが明確で合理的
- リスクが許容可能で管理可能

### NO-GO基準
- 根本的なアーキテクチャの衝突
- 重大な要件が対処されていない
- 実装アプローチに高い失敗リスク
- 設計の複雑さが要件に対して不釣り合い

## 使用例

```bash
# 設計を検証
/kiro:validate-design user-authentication
```

## 次のフェーズ

検証後：
- **GOの場合**: `/kiro:spec-tasks <feature-name>` でタスク生成
- **自動承認で進行**: `/kiro:spec-tasks <feature-name> -y`
