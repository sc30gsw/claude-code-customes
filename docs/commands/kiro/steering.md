# Kiro Steering Command

## 概要

プロジェクトの状態に基づいてKiro steeringドキュメントをインテリジェントに作成・更新するコマンド。spec-driven developmentのための正確なプロジェクト知識を維持します。

## 基本情報

| 項目 | 値 |
|------|-----|
| コマンド | `/kiro:steering` |
| 用途 | Steeringドキュメントの作成・更新 |
| 許可ツール | Bash, Read, Write, Edit, MultiEdit, Glob, Grep, LS |

## Steeringドキュメント

### コアファイル（常に読み込み）

#### product.md - プロダクト概要
- プロダクトの説明
- コア機能
- ターゲットユースケース
- 主要な価値提案

#### tech.md - 技術スタック
- アーキテクチャ
- フロントエンド/バックエンド技術
- 開発環境
- 共通コマンド
- 環境変数
- ポート設定

#### structure.md - プロジェクト構造
- ルートディレクトリ構成
- サブディレクトリ構造
- コード構成パターン
- ファイル命名規則
- インポート構成
- 主要なアーキテクチャ原則

## スマート更新戦略

### 新規ファイル（"📝 Not found"）
プロジェクトのすべての側面をカバーする包括的な初期コンテンツを生成。

### 既存ファイル（"✅ EXISTS"）
1. **ユーザーカスタマイズを保持** - 手動編集やカスタムセクション
2. **事実情報を更新** - 依存関係、ファイル構造、コマンド
3. **新しいセクションを追加** - 重要な新機能がある場合のみ
4. **非推奨コンテンツをマーク** - 削除ではなくマーク
5. **フォーマットを維持** - 既存のスタイルと一貫性を保つ

## 使用例

```bash
# Steeringドキュメントを作成/更新
/kiro:steering

# 更新前の状態を確認
ls -la .kiro/steering/
```

## インクルージョンモード

| モード | 用途 |
|--------|------|
| Always | ビジネスコンテキスト、技術制約、アーキテクチャ決定 |
| Conditional | 特定のファイルパターンに一致する場合のみ |
| Manual | @filename構文でオンデマンド参照 |

## セキュリティガイドライン

- **機密データを含めない**: APIキー、パスワード、認証情報なし
- **コミット前にレビュー**: バージョン管理前に内容を確認
- **チーム共有を考慮**: steeringファイルはチームで共有

## コンテンツ品質ガイドライン

- **単一ドメインフォーカス**: 各ファイルは1つの特定領域をカバー
- **明確で説明的**: 具体例と決定の根拠を提供
- **定期的なメンテナンス**: 主要なプロジェクト変更後にレビュー・更新
- **実行可能なガイダンス**: 抽象的な原則より具体的で実装可能なガイドライン
