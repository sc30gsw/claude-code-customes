# OKR設定支援コマンド

チームの上位目標に基づいて、個人の四半期OKRを対話的に作成支援するコマンドです。

## `/okr` - OKR設定支援コマンド

### 概要
チームの上位目標と役割に基づいて、個人の四半期OKRを作成支援します。3つのObjectiveと各Objectiveに3つのKey Result（合計9つ）を生成し、各Key Resultには70%（通常目標）と100%（ストレッチ目標）の2段階達成基準を設定します。

### 基本構文
```bash
/okr --role <role> "<team-goals>"
```

### 引数
| 引数 | 必須 | 説明 |
|------|------|------|
| `--role` | はい | 役割（engineer, pm, designer, qa, data-analyst等） |
| `<team-goals>` | はい | チームの上位目標（自然言語テキスト） |

### 対応役割一覧

| 役割 | 略称 | 主なフォーカス領域 |
|------|------|------------------|
| `engineer` | - | 技術成果、開発効率、コード品質、スキル向上 |
| `pm` | - | プロダクト指標、機能リリース、ユーザーフィードバック |
| `designer` | - | UX/UI改善、デザインシステム、ユーザビリティ |
| `qa` | - | 品質指標、テスト自動化、リリース品質 |
| `data-analyst` | `da` | データ品質、分析レポート、データパイプライン |

### 使用例

#### エンジニア向けOKR作成
```bash
/okr --role engineer "売上20%増加、顧客満足度NPS+10向上、新規プロダクト2件リリース"
```

#### プロダクトマネージャー向けOKR作成
```bash
/okr --role pm "チーム生産性向上、品質改善、技術負債削減"
```

#### デザイナー向けOKR作成
```bash
/okr --role designer "UX改善、デザインシステム構築、ブランド統一"
```

#### QAエンジニア向けOKR作成
```bash
/okr --role qa "バグ件数50%削減、テストカバレッジ80%達成、リリースサイクル短縮"
```

#### データアナリスト向けOKR作成
```bash
/okr --role data-analyst "データ品質向上、セルフサービスBI構築、データドリブン文化醸成"
```

### 処理ワークフロー

#### Phase 1: チーム上位目標の分析
1. **引数のパース**: `--role`オプションとチーム目標テキストを抽出
2. **優先事項の抽出**: チーム目標から複数の優先事項を特定
3. **役割との関連性整理**: 指定された役割がどのように各優先事項に貢献できるか分析

**Sequential Thinkingを使用して**:
- チーム目標の構造を分析
- 隠れた優先事項や依存関係を特定
- 役割に適したフォーカスエリアを決定

#### Phase 2: Objective設計（3つ）
1. チーム目標の各優先事項に対応するObjective候補を3つ生成
2. 各Objectiveが異なる側面をカバーするよう調整
3. 役割に特化した表現に最適化

#### Phase 3: Key Result設計（合計9つ）
1. 各Objectiveに対して測定可能なKRを3つ生成
2. 各KRに70%（通常）と100%（ストレッチ）の2段階目標を設定
3. SMART原則に基づく数値目標の妥当性を検証

#### Phase 4: 出力＆レビュー
1. 完成したOKRを整形して出力
2. 全体整合性チェック
3. 調整の機会を提供

### 出力フォーマット

処理完了時の出力例：

```markdown
# 四半期OKR（FY2025 Q1）

## あなたの役割
Engineer

## チーム上位目標との関連
売上20%増加、顧客満足度NPS+10向上、新規プロダクト2件リリース

### 抽出された優先事項
1. 売上向上に貢献する機能開発
2. 顧客満足度を高める品質改善
3. 新規プロダクトの技術基盤構築

---

## Objective 1: プロダクト価値を最大化する高品質な機能を迅速にデリバリーする
> ユーザーに真の価値を届け、売上成長に直接貢献する

### Key Result 1.1: 機能リリース数
| 達成度 | 目標 |
|--------|------|
| 70%達成 | 主要機能を5件リリース |
| 100%達成 | 主要機能を8件リリース |

### Key Result 1.2: リリースサイクル短縮
| 達成度 | 目標 |
|--------|------|
| 70%達成 | 平均リリースサイクルを2週間に短縮 |
| 100%達成 | 平均リリースサイクルを1週間に短縮 |

### Key Result 1.3: 本番障害ゼロリリース
| 達成度 | 目標 |
|--------|------|
| 70%達成 | 重大障害を起こすリリースを1件以下 |
| 100%達成 | 重大障害を起こすリリースをゼロ |

---

[Objective 2, 3も同様の構造で続く...]

---

## サマリー

| Objective | Key Results数 | チーム目標との関連 |
|-----------|--------------|------------------|
| O1: プロダクト価値最大化 | 3 | 売上向上 |
| O2: 技術負債削減 | 3 | 顧客満足度向上 |
| O3: 新技術基盤構築 | 3 | 新規プロダクト |
```

### OKR設計のベストプラクティス

#### 良いObjectiveの特徴
| DO | DON'T |
|----|-------|
| 野心的で刺激的な表現を使う | 数値を含めない（それはKRの役割） |
| チーム目標との明確なつながりを示す | 曖昧すぎる表現を避ける |
| 達成可能かつチャレンジング | 複数の異なる方向性を混ぜない |

#### 良いKey Resultの特徴（SMART）
| 原則 | 説明 |
|------|------|
| **S**pecific | 具体的で明確 |
| **M**easurable | 測定可能な数値目標 |
| **A**chievable | 達成可能（挑戦的だが現実的） |
| **R**elevant | Objectiveと関連性がある |
| **T**ime-bound | 四半期内に期限付き |

#### 70%/100%達成基準の設定ガイドライン

| 達成度 | 意味 | 設定の考え方 |
|--------|------|-------------|
| **70%達成** | 通常目標 | 努力すれば高確率で達成可能。「頑張れば達成できる」レベル |
| **100%達成** | ストレッチ目標 | 全てがうまくいった場合に達成可能。「最高の状態で全てがうまくいけば」レベル |

**評価の目安**:
- 70%達成で「成功」と評価
- 100%達成で「卓越」と評価

### 役割別の考慮事項

#### Engineer
- 技術的な成果物（コード品質、パフォーマンス改善など）
- 開発効率の向上（CI/CD、自動化など）
- 技術負債の削減
- 学習・スキル向上

#### PM (Product Manager)
- プロダクト指標（DAU、リテンション、コンバージョンなど）
- 機能リリース数・品質
- ユーザーフィードバック対応
- ステークホルダー調整

#### Designer
- UX/UI改善指標（タスク完了率、エラー率など）
- デザインシステム構築・普及
- ユーザビリティテスト結果
- ブランド一貫性

#### QA
- 品質指標（バグ検出率、カバレッジ、回帰テストなど）
- テスト自動化率
- リリース品質ゲート
- 品質プロセス改善

#### Data Analyst
- データ品質指標（精度、鮮度、カバレッジ）
- 分析レポート・ダッシュボード提供数
- データドリブン意思決定支援
- データパイプライン改善

### 活用シーン
- **四半期開始時**: 新しい四半期のOKR設定
- **チーム目標展開時**: チーム目標から個人OKRへの落とし込み
- **1on1準備**: 上司との目標すり合わせ前の下書き作成
- **キャリア開発**: 成長目標と業務目標のバランス確認

### Tips
- OKRは四半期ごとに見直すことを推奨
- 進捗は週次または隔週でチェック
- 状況変化に応じて柔軟に調整可能
- チームメンバーや上司と共有・すり合わせを行う
- 70%達成が「失敗」ではないことを理解する
- Key Resultは「活動」ではなく「成果」を記述する

### 使用ツール
- `mcp__sequential-thinking__sequentialthinking` - チーム目標の分析と構造化
- `TodoWrite` - OKR作成進捗管理
- `Read` - 既存ドキュメントの参照
- `Write` - OKRドキュメントの出力
- `Glob` - 関連ファイルの検索

### 関連コマンド
- `/sc:brainstorm` - 目標設定前のアイデア出し
- `/sc:estimate` - 目標達成に必要な工数見積もり
- `/message --format report` - OKR進捗レポートの作成
