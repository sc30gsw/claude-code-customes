# OKR設定支援コマンド

チームの上位目標に基づいて、個人の四半期OKRを対話的に作成支援するコマンドです。ファイル参照、インタラクティブモード、セッション永続化機能を備えています。

## `/okr` - OKR設定支援コマンド

### 概要
チームの上位目標と役割に基づいて、個人の四半期OKRを作成支援します。3つのObjectiveと各Objectiveに3つのKey Result（合計9つ）を生成し、各Key Resultには70%（通常目標）と100%（ストレッチ目標）の2段階達成基準を設定します。

### 基本構文
```bash
/okr --role <role> "<team-goals>" [options]
```

---

## 引数一覧

### 必須引数
| 引数 | 説明 |
|------|------|
| `--role <role>` | 役割（engineer, pm, designer, qa, data-analyst等） |
| `<team-goals>` | チームの上位目標（自然言語テキスト） |

### ファイル/ディレクトリ入力オプション
| オプション | 説明 | 使用例 |
|------------|------|--------|
| `--sample <path>` | OKRサンプルファイル参照 | `--sample ./okrs/samples/engineer.md` |
| `--team-okr <path>` | チームOKRファイル参照 | `--team-okr ./okrs/team/2025-Q1.md` |
| `--context <path>` | 追加コンテキストファイル | `--context ./strategy.md` |
| `--previous <path>` | 前四半期OKR参照 | `--previous ./okrs/personal/2024-Q4.md` |
| `--mission <path>` | ミッションファイル | `--mission ./company/mission.md` |
| `--values <path>` | 価値観ファイル | `--values ./company/values.md` |

### 出力オプション
| オプション | 説明 | デフォルト |
|------------|------|-----------|
| `--output <path>` | 出力先ファイルパス | コンソール出力 |
| `--format <type>` | 出力形式: markdown/json/yaml | markdown |

### インタラクティブ機能
| オプション | 説明 |
|------------|------|
| `--interactive` | 対話形式でOKR作成 |
| `--refine` | 曖昧な目標を質問で具体化 |

### ヘルパーオプション
| オプション | 説明 |
|------------|------|
| `--quarter <Q1-Q4>` | 対象四半期を指定 |
| `--year <YYYY>` | 対象年度を指定 |
| `--strengths <desc>` | 個人の強みを指定 |
| `--growth <desc>` | 成長領域を指定 |

### 高度なオプション
| オプション | 説明 |
|------------|------|
| `--benchmark` | 業界ベンチマークを参照 |
| `--persist` | セッションをSerenaメモリに保存 |
| `--resume` | 前回セッションから再開 |

## 使用例

### 基本的な使用方法
```bash
/okr --role engineer "売上20%増加、顧客満足度NPS+10向上、新規プロダクト2件リリース"
```

### サンプル参照付きOKR作成
```bash
/okr --role engineer "売上20%増加" --sample ./okrs/samples/engineer.md
```

### チームOKR + ミッション整合性確認
```bash
/okr --role pm "チーム成長" --team-okr ./okrs/team/2025-Q1.md --mission ./company/mission.md
```

### インタラクティブモード + セッション永続化
```bash
/okr --role engineer --interactive --persist
```

### JSON形式でファイル出力
```bash
/okr --role designer "UX改善" --format json --output ./okrs/personal/2025-Q1.json
```

### 前四半期からの継続
```bash
/okr --role engineer "継続改善" --previous ./okrs/personal/2024-Q4.md --refine
```

### セッション再開
```bash
/okr --resume
```

## 処理ワークフロー

### Phase 1: 引数パース＆コンテキスト読み込み
1. **引数のパース**: 全オプションとフラグを抽出
2. **参照ファイルの読み込み**: 指定されたファイル（sample, team-okr, context等）を読み込み
3. **セッション確認**: `--resume`の場合、Serenaメモリから読み込み
4. **入力検証**: 必須引数の存在確認

### Phase 2: チーム上位目標の分析
1. **優先事項の抽出**: チーム目標から複数の優先事項を特定
2. **役割との関連性整理**: 指定された役割がどのように各優先事項に貢献できるか分析
3. **コンテキスト統合**: ミッション/価値観ファイルが提供された場合は統合

**Sequential Thinkingを使用して**:
- チーム目標の構造を分析
- 隠れた優先事項や依存関係を特定
- 役割に適したフォーカスエリアを決定
- チームOKRが提供された場合は相互参照

### Phase 3: インタラクティブ精緻化（--interactive または --refine の場合）
対話形式で以下の質問を通じてOKRを具体化：
1. 「これらの目標達成における現在の課題は何ですか？」
2. 「この四半期で伸ばしたい特定のスキルはありますか？」
3. 「目標達成に影響する依存関係やブロッカーはありますか？」
4. 「明らかな指標以外に、どのように成功を測定しますか？」
5. 「必要なリソースやサポートはありますか？」

### Phase 4: Objective設計（3つ）
1. チーム目標の各優先事項に対応するObjective候補を3つ生成
2. 各Objectiveが異なる側面をカバーするよう調整
3. 役割に特化した表現に最適化
4. サンプルが提供された場合はパターンを踏襲

### Phase 5: Key Result設計（合計9つ）
1. 各Objectiveに対して測定可能なKRを3つ生成
2. 各KRに70%（通常）と100%（ストレッチ）の2段階目標を設定
3. SMART原則に基づく数値目標の妥当性を検証
4. ベンチマークが要求された場合は業界標準を調査

### Phase 6: 出力生成
1. 指定された形式（markdown/json/yaml）で出力を生成
2. `--output`が指定された場合はファイルに書き込み

### Phase 7: セッション永続化（--persist の場合）
1. Serenaメモリにセッションデータを保存
2. 役割、目標、生成されたOKR、タイムスタンプを含む

## セッション管理

### セッションの保存
```bash
/okr --role engineer "goals" --persist
```
セッションをSerenaメモリに保存し、後で再開できます。

### セッションの再開
```bash
/okr --resume
```
前回のセッションを読み込み、中断したところから再開します。

### 保存済みセッションの確認
Serenaメモリツールを使用して確認できます：
- 全メモリ一覧: `mcp__serena__list_memories()`
- 特定メモリ読み込み: `mcp__serena__read_memory("okr_session")`

## OKR設計のベストプラクティス

### 良いObjectiveの特徴
| DO | DON'T |
|----|-------|
| 野心的で刺激的な表現を使う | 数値を含めない（それはKRの役割） |
| チーム目標との明確なつながりを示す | 曖昧すぎる表現を避ける |
| 達成可能かつチャレンジング | 複数の異なる方向性を混ぜない |

### 良いKey Resultの特徴（SMART）
| 原則 | 説明 |
|------|------|
| **S**pecific | 具体的で明確 |
| **M**easurable | 測定可能な数値目標 |
| **A**chievable | 達成可能（挑戦的だが現実的） |
| **R**elevant | Objectiveと関連性がある |
| **T**ime-bound | 四半期内に期限付き |

### 70%/100%達成基準の設定ガイドライン

| 達成度 | 意味 | 設定の考え方 |
|--------|------|-------------|
| **70%達成** | 通常目標 | 努力すれば高確率で達成可能。「頑張れば達成できる」レベル |
| **100%達成** | ストレッチ目標 | 全てがうまくいった場合に達成可能。「最高の状態で全てがうまくいけば」レベル |

**評価の目安**:
- 70%達成で「成功」と評価
- 100%達成で「卓越」と評価

## 役割別の考慮事項

### Engineer
- 技術的な成果物（コード品質、パフォーマンス改善など）
- 開発効率の向上（CI/CD、自動化など）
- 技術負債の削減
- 学習・スキル向上

### PM (Product Manager)
- プロダクト指標（DAU、リテンション、コンバージョンなど）
- 機能リリース数・品質
- ユーザーフィードバック対応
- ステークホルダー調整

### Designer
- UX/UI改善指標（タスク完了率、エラー率など）
- デザインシステム構築・普及
- ユーザビリティテスト結果
- ブランド一貫性

### QA
- 品質指標（バグ検出率、カバレッジ、回帰テストなど）
- テスト自動化率
- リリース品質ゲート
- 品質プロセス改善

### Data Analyst
- データ品質指標（精度、鮮度、カバレッジ）
- 分析レポート・ダッシュボード提供数
- データドリブン意思決定支援
- データパイプライン改善

## 活用シーン

- **四半期開始時**: 新しい四半期のOKR設定
- **チーム目標展開時**: チーム目標から個人OKRへの落とし込み
- **1on1準備**: 上司との目標すり合わせ前の下書き作成
- **キャリア開発**: 成長目標と業務目標のバランス確認
- **継続的改善**: 前四半期のOKRを参照した継続設定

---

## Tips

- OKRは四半期ごとに見直すことを推奨
- 進捗は週次または隔週でチェック
- 状況変化に応じて柔軟に調整可能
- チームメンバーや上司と共有・すり合わせを行う
- 70%達成が「失敗」ではないことを理解する
- Key Resultは「活動」ではなく「成果」を記述する
- サンプルファイルを参考に、自分の状況に合わせてカスタマイズ
