# API Client (aspida + up-fetch)

## Responsibilities of `src/lib/api-client.ts`

Centralize HTTP configuration in one place. Authentication headers, timeouts, and error handling belong here—not in feature API files.

```typescript
// src/lib/api-client.ts

// ! Returning the Response as-is in parseResponse satisfies @aspida/fetch's fetch-compatible interface
const aspidaUpfetch = up(fetch, () => ({
  headers: {
    Authorization: authStorage.getToken() ?? undefined,
  },
  onError: handleResponseError,
  parseRejected: parseErrorResponse,
  parseResponse: (response: Response) => response,
  timeout: API_TIMEOUT_MS,
}))

//? RequestInit.signal is AbortSignal | null | undefined, but up-fetch does not accept null, so convert it to undefined
const authFetch = (input: RequestInfo | URL, init?: RequestInit) => {
  const { signal, ...rest } = init ?? {}
  return aspidaUpfetch(input, { ...rest, signal: signal ?? undefined })
}

export const apiClient = api(aspida(authFetch, { baseURL: API_BASE_URL }))
```

Authentication errors (401/403) and 404 are handled uniformly by `handleResponseError`, `handleAuthError`, and `handleNotFoundError`.

## Do not manually edit `src/lib/aspida/`

Everything under `src/lib/aspida/` is auto-generated by `openapi2aspida`. Manual edits will be overwritten on the next regeneration.

```
// WRONG: editing generated files directly
// src/lib/aspida/$api.ts ← DO NOT TOUCH

// CORRECT: regenerate when the OpenAPI spec changes
pnpm generate:api
```

## Wrap in `features/*/api/` and return `Result`

Do not call the aspida `apiClient` directly from hooks or components. Wrap it in a feature API module and return `Result`.

```typescript
// features/mail-groups/api/mutations.ts
import { Result } from 'better-result'
import { apiClient } from '~/lib/api-client'
import { toApiError } from '~/utils/to-api-error'

export function createMailGroup(input: CreateMailGroupInput) {
  return Result.tryPromise({
    catch: toApiError,
    try: async () => {
      const response = await apiClient.api.v1.mail_groups.$post({
        body: {
          mail_group: {
            name: input.name,
            // ...
          },
        },
      })
      return response
    },
  })
}

export function deleteMailGroup(id: MailGroup['id']) {
  return Result.tryPromise({
    catch: toApiError,
    try: async () => {
      await apiClient.api.v1.mail_groups._id(id).$delete()
      return null
    },
  })
}
```

`toApiError` is defined in `~/utils/to-api-error.ts`. Always use it for `catch`.

## aspida endpoint call patterns

```typescript
// GET /api/v1/mail_groups
apiClient.api.v1.mail_groups.$get({ query: { page: 1 } })

// POST /api/v1/mail_groups
apiClient.api.v1.mail_groups.$post({ body: { mail_group: {...} } })

// DELETE /api/v1/mail_groups/:id
apiClient.api.v1.mail_groups._id(id).$delete()

// Nested endpoints
apiClient.api.v1.mail_groups._mail_group_id(id).notification_mails.$get({ query: { ... } })
```
